Необходимо реализовать приложение «Чек-лист завершения операций ВСП/РФ» для обработки операций контроля заврешению операционного дня сотрудниками РФ. 
На текущий момент количество РФ участников -63, количество ВСП РФ участников - 1363. При завершении каждого рабочего дня ВСП/РФ, один ответственный сотрудник каждого ВСП РФ участника должен зайти в приложение «Чек-лист завершения операций ВСП/РФ» и обработать соответствующие операции контроля  для проведения совокупного комплекса проверок полноты и правильности формирования бухгалтерских записей, выполнение которых является обязательным до процесса блокирования операционного дня и должно осуществляться ответственными сотрудниками за осуществление учетных операций в балансе на основании первичных документов с помощью отчетов и других возможностей АБС. 
В Приложении предусмотреть 2 рабочих панели:
–	Панель сотрудника РФ/ВСП
–	Административная панель для сотрудников ЕСЦ
В приложении предусмотреть справочник с перечнем РФ, ВСП по каждому РФ и графику работы ВСП.
Панель сотрудника РФ/ВСП
Основные критерии при использовании панли сотрудника РФ/ВСП:
–	На один ВСП в день может быть создана только одна проверка (независимо от того, завершена она или является черновиком). 
–	Один пользователь не может иметь более одного незавершённого черновика за текущую дату. 
–	Если филиал пользователя заблокирован (поле blocked в таблице filials), создание новых проверок полностью запрещено. 
–	Выбор между стандартными и альтернативными фильтрами при заполнении чек-листа зависит от настройки филиала (поле check_name в таблице filials). 
–	Удаление черновика разрешено только его владельцу; при удалении каскадно удаляются все связанные ответы.
При входе в приложение открывается экранная форма, разделённая на две зоны. Левая боковая панель содержит информацию о текущем пользователе (ФИО, логин), кнопку смены пользователя и блок входа в административную панель. Центральная область представлена набором вкладок, каждая из которых отвечает за отдельный функциональный блок: «Новая проверка», «История проверок», «Нерабочие дни ВСП», «Аналитика по филиалу», «Визуализация».
–	Вкладка «Новая проверка» -  позволяет создавать новые черновики Чек-листа путем нажатия на кнопку «Начать заполнение». При этом, если за указанную дату уже есть черновик или завершенный Чек-лист по указанному ВСП, то никто в этом ВСП не может больше начать заполнение чек листа повторно. При открытии вкладки автоматически отображаются ФИО и логин пользователя. ВСП подставлено по умолчанию из данных авторизации. Пользователь может изменить ВСП через выпадающий список, который формируется из таблицы vsp: выбираются все записи с кодом филиала пользователя и признаком активности close_vsp = false, отсортированные по наименованию. Дата проверки всегда равна текущему дню и недоступна для редактирования.
Возможны два способа Авторизации и заполнения начальных данных:
–	Первый — через корпоративную систему аутентификации Keycloak. 
–	Второй  — через указание вручную логина в формате rf_familiya_io 
Пользователь вводит логин. Система обращается к таблице users и по полю name находит запись сотрудника. Из этой записи извлекаются: полное имя (full_name), код филиала (name_filial), обозначение ВСП (name_vsp). Код филиала используется для поиска в таблице filials — оттуда берутся идентификатор и наименование филиала, а также признак блокировки (blocked). Обозначение ВСП сопоставляется с таблицей vsp — извлекаются идентификатор, наименование и дополнительное обозначение ВСП.
Если пользователь не найден, выводится сообщение об ошибке. Если филиал заблокирован (поле blocked имеет значение «истина»), доступ к приложению запрещается — пользователь видит предупреждение, и все дальнейшие действия блокируются.
После успешной авторизации все данные (ФИО, логин, филиал, ВСП, признак блокировки) сохраняются и используются на всех последующих шагах.
Перед созданием новой проверки (черновика), система выполняет три проверки:
–	Первая: ищется незавершённый черновик текущего пользователя за сегодня. Просматривается таблица checklist_sessions — если существует запись, где user_name совпадает с логином пользователя, operation_date равна сегодняшней дате, а status_bul имеет значение «ложь», то черновик найден. В этом случае вместо кнопки создания проверки показываются кнопки «Продолжить» и «Удалить» для этого черновика.
–	Вторая: проверяется, нет ли уже любой сессии (завершённой или черновика) для выбранного ВСП на сегодняшнюю дату. В таблице checklist_sessions ищется запись, где vsp_id совпадает с выбранным ВСП, а operation_date равна текущей дате. Если такая запись существует, создание новой блокируется, так как на одно ВСП в день допускается только одна проверка.
–	Третья: проверяется флаг блокировки филиала, сохранённый при авторизации. Если филиал заблокирован, кнопка начала проверки недоступна.
Если все проверки пройдены, при нажатии кнопки «Начать заполнение» создаётся новая сессия: в таблицу checklist_sessions добавляется строка с логином пользователя, идентификатором филиала, идентификатором ВСП, текущей датой и статусом «черновик» (status_bul = false). Интерфейс переключается на форму заполнения чек-листа.


В левой части ЭФО отражается запись «Идет заполнение чек-листа». В центральной части после создания или продолжения черновика загружаются: шаблон проверок из таблицы checklist_templates (все пункты, отсортированные по полю item_order) и сохранённые ответы из таблицы checklist_answers для текущей сессии (по session_id). Дополнительно по филиалу сессии из таблицы filials определяется значение поля check_name. Если оно истинно, для отображения используются альтернативные поля шаблона (с префиксом alt_), иначе — стандартные.



Для каждого пункта шаблона выводятся: порядковый номер (item_order), наименование (description), кнопка «Подробнее», раскрывающая два фильтра (основной и дополнительный). В тексте фильтров динамически подставляются: текущая дата в нескольких форматах (плейсхолдеры [Дата1], [Дата1 гггг-мм-дд], [Дата1 дд.мм.гггг]), полное название ВСП (плейсхолдер [РФ]) и первые три символа названия ВСП (плейсхолдер [РФ1]). Рядом с каждым фильтром есть кнопка копирования текста в буфер обмена.


Для каждого пункта отображается чекбокс «Выполнено» (состояние связано с полем is_completed в таблице checklist_answers) 
Также на данной ЭФО настроены кнопки управления:
«Сохранить черновик» — при сохранении черновика, сотрудник может выйти из приложения и при повторном входе на стратовой странице приложения повится запись о незаверешенном черновике и 2 кнопки: Продолжить и Удалить. При нажатии на кнопку Продолжить откроется форма черновика Чек-листа для его заврешения. При нажатии на кнопку Удалить, черновик Чек-листа удалится. Для каждого пункта, где были изменения, выполняется вставка или обновление записи в таблице checklist_answers (по паре session_id и template_item_id). Статус сессии остаётся «черновик». Сессия помечается как явно сохранённая.

«Назад» — если черновик ни разу не был явно сохранён, сессия и все её ответы удаляются (сначала из checklist_answers, затем из checklist_sessions). Если черновик сохранялся, происходит возврат к вкладке «Новая проверка» без удаления.
«Предпросмотр» — показывает количество выполненных пунктов и общее количество пунктов в шаблоне (без запросов к базе, на основе локальных данных).


«Завершить проверку»  при нажатии проверяется, что все пункты отмечены. Если не все — выводится предупреждение. Если все выполнены — сохраняются ответы, сессия получает статус «завершена» (status_bul = true), фиксируется время завершения (completed_at). После этого интерфейс возвращается на вкладку «Новая проверка».

–	Вкладка «История проверок» - Отображает таблицу всех проверок текущего пользователя в его ВСП  и позволяет удалять черновики пользователя в его ВСП. Данные формируются одним запросом, который объединяет таблицы checklist_sessions, filials и vsp. Для каждой сессии вычисляется количество выполненных ответов (подсчёт записей в checklist_answers с is_completed = true) и общее количество пунктов шаблона (отдельный подзапрос к checklist_templates).
Столбцы таблицы: идентификатор сессии (checklist_sessions.id), дата проверки (operation_date), филиал (filials.name), ВСП (vsp.name), статус (вычисляется: «Завершена», если status_bul истинен, иначе «Черновик»), дата и время начала (created_at), дата и время завершения (completed_at, может быть пустым для черновиков), количество выполненных проверок, общее количество проверок.
При выборе сессии и нажатии «Показать результаты» загружаются полные данные: сама сессия, все её ответы с отметками о выполнении, а также шаблон чек-листа. Результаты выводятся в виде списка пунктов с указанием статуса каждого.
Для использования функции «Удалить черновик по ID» пользователь вводит идентификатор сессии; система проверяет, что сессия принадлежит ему и имеет статус «Черновик». При нажатии на кнопку «Удалить» удаляются все ответы и сама сессия.

–	Вкладка «Нерабочие дни ВСП» - позволяет внести информацию по нерабочим дням ВСП
ВСП автоматически подставлено из данных пользователя, но может быть изменено через список активных ВСП филиала (запрос к vsp с фильтром по filial_id и close_vsp = false). Пользователь выбирает дату из календаря и причину из выпадающего списка (ремонтные работы, праздничный день и т.д.). Предусмотреть возможность при выборе из списка причины «Другое», вносить ручные корректировки для полноты описания причины. При сохранении в таблицу vsp_non_working_days добавляется запись с логином пользователя, кодом филиала, идентификатором ВСП, датой и причиной.
ПРи использовании функции «Ранее добавленные нерабочие дни», записи извлекаются из vsp_non_working_days с присоединением справочников filials и vsp для получения читаемых названий. По умолчанию показываются только записи для выбранного ВСП. При установке флажка «Показать все выходные вашего ВСП» отображаются все записи этого ВСП (фильтр по vsp_id сохраняется). Для каждой записи выводится кнопка «Удалить». При удалении проверяется, что запись относится к тому же ВСП и филиалу, что и текущий пользователь.

–	Вкладка «Аналитика по филиалу» -  позволяет увидеть проверки по ВСП, управлять черновиками и содержит список всех проверок.
Филиал автоматически определён. Пользователь может выбрать период дат через два календаря.
Таблица всех проверок строится запросом, аналогичным истории, но без фильтрации по пользователю — показываются все сессии филиала. Столбцы: идентификатор сессии, сотрудник (поле user_name), дата, ВСП, статус, дата и время начала, дата и время завершения, количество выполненных проверок.
В блоке «Управления черновиками» отображаются только сессии со статусом «Черновик», дополнительно отфильтрованные по ВСП текущего пользователя. Пользователь может выбрать несколько черновиков и удалить их, предварительно подтвердив действие. При удалении для каждой выбранной сессии каскадно удаляются ответы и сама сессия.


–	Вкладка «Визуализация» - показывает статус заполнения чек-листов для всех ВСП филиала на выбранную дату. Пользователь видит свой филиал (автоматически определён) и выбирает дату.
При нажатии «Показать статус» система получает: перечень всех активных ВСП филиала (из vsp), множество ВСП с нерабочим днём на выбранную дату (из vsp_non_working_days) и множество ВСП с завершённой проверкой на эту дату (из checklist_sessions с условием status_bul = true). Для каждого ВСП определяется статус: если ВСП есть в списке нерабочих — «Выходной»; иначе если есть завершённая проверка — «Заполнен»; иначе — «Не заполнен».
Строится круговая диаграмма, где ВСП со статусом «Выходной» исключаются из расчёта долей. Оставшиеся делятся на «Заполнено» (зелёный) и «Не заполнено» (красный) с процентным соотношением. Под диаграммой — таблица со столбцами «ВСП» и «Статус», строки которой раскрашены в зависимости от статуса.

Административная панель Чек-листа
Ключевые бизнес-правила административной части:
–	При удалении пункта шаблона каскадно удаляются все связанные с ним ответы, после чего оставшиеся пункты автоматически перенумеровываются для сохранения непрерывной последовательности. 
–	При массовых операциях с нерабочими днями перед созданием каждой записи проверяется её отсутствие для того же ВСП на ту же дату — дубликаты не создаются. 
–	Установка блокировки филиала немедленно запрещает пользователям этого филиала создавать новые проверки, но не затрагивает уже существующие черновики. 
–	Флаг альтернативных фильтров влияет на то, какие поля шаблона увидят пользователи филиала при заполнении чек-листа. 
–	При возврате завершённой сессии в черновик у неё очищается дата завершения и меняется статус, что делает её снова доступной для редактирования.
–	Возможность самостоятельного управления справочником РФ и ВСП для добавления/удаления РФ или ВСП по причине открытия/закрытия с соответствующими автоматическими корректировками по всем необходимым вкладкам в Чек-листе.
Административная панель доступна после проверки прав. Возможны два способа входа:
–	Первый — через корпоративную систему аутентификации Keycloak: если email пользователя содержится в заранее определённом списке администраторов (хранится в конфигурации приложения), вход в режим администратора происходит автоматически при установке флажка на боковой панели. 
–	Второй — через ввод пароля: если вход через Keycloak не используется или email отсутствует в списке, администратор вводит пароль в текстовое поле. Пароль сравнивается с заданным значением, хранящимся в конфигурации приложения. При совпадении режим администратора активируется.
После успешной активации на боковой панели появляются дополнительные элементы управления, а в центральной области добавляются новые вкладки: «Аналитика», «Филиалы (чекбоксы)», «Нерабочие дни (отчет)», «Визуализация (админ)», «Витрины (админ)».
Левая боковая панель (административные функции)

В свёрнутом блоке «Текущие проверки» отображается список всех пунктов чек-листа. Данные загружаются из таблицы checklist_templates (поля item_order и description), сортировка по порядковому номеру. Для каждого пункта показывается его номер и наименование.

Блок «Добавить проверку» позволяет добавить новую проверку в контрольные процедуры чек-листа. Для добавления новой проверки в шаблон в расширенном блоке администратор заполняет текстовые поля: наименование проверки, описание, основной фильтр, дополнительный фильтр, альтернативный фильтр, альтернативное описание, альтернативный дополнительный фильтр. Все эти данные будут сохранены в соответствующих полях таблицы checklist_templates (description, additional_info, filter_value, events_value, alt_filter_value, alt_additional_info, alt_events_value). При заполнении необходимых полей необходимо нажать на кнопку “Добавить”
Также можно выбрать позицию вставки/перемещения проверки между пунктами: либо в конец списка, либо перед конкретным существующим пунктом. Если выбрана позиция не в конец, все существующие пункты с порядковым номером, большим или равным указанному, сдвигаются на единицу вперёд, после чего новый пункт вставляется на освободившееся место. Это позволяет управлять порядком проверок без ручной перенумерации.

Блок «Редактировать/Удалить/Переместить“ позволяет выбрать проверку для внесения корректировок в любое из полей, добавленных ранее.
Администратор выбирает пункт из выпадающего списка, где для каждого элемента показан его идентификатор и первые символы наименования. При выборе загружаются текущие значения всех полей из таблицы checklist_templates. Администратор может изменить любое поле и сохранить изменения нажатием на кнопку ”Обновить”. Выполняется обновление записи в таблице по идентификатору пункта.


Если необходимо удалить проверку, то нажать на кнопку “Удалить”. При удалении выполняются три операции. Сначала удаляются все ответы, связанные с этим пунктом, из таблицы checklist_answers (по полю template_item_id). Затем удаляется сам пункт из таблицы checklist_templates. После этого происходит автоматическая перенумерация оставшихся пунктов: каждому присваивается новый порядковый номер на основе текущей сортировки, чтобы последовательность оставалась непрерывной.
Поддерживается два способа перемещения. Первый — сдвиг вверх или вниз на одну позицию: система находит соседний пункт (с предыдущим или следующим порядковым номером) и меняет их номера местами. Второй — перемещение на конкретную позицию: в зависимости от направления перемещения все промежуточные пункты сдвигаются на единицу, а перемещаемый пункт получает новый номер. Оба способа работают через обновление поля item_order в таблице checklist_templates.

 Центральная часть ЭФО административной панели содержит набор вкладок с информационным полем:
–	вкладка "Новая проверка" – позволяет создавать новые черновики Чек-листа путем нажатия на кнопку «Начать заполнение». 
При этом, если за указанную дату уже есть черновик или завершенный Чек-лист по указанному ВСП, то никто в этом ВСП не может больше начать заполнение чек листа повторно.На данной вкладке должно быть указано ФИО авторизованного пользователя, его логин, ВСП сотрудника. Авторизация пользователя и определение ВСП сотрудника должно происходить автоматически. Дата всегда равна дате текущего дня и недоступна для корректировки пользователю. Предусмотреть также на вкладке «Новая проверка» возможность изменения ВСП пользователя. 
–	вкладка «История проверок» – хранит информацию по обработке и завершению авторизованным пользователем Чек-листа в табличной форме, имеющим набор полей: id сессии, дата проверки, филиал, ВСП, статус проверки, Дата и время начала, Дата и время заверешения, кол-во выполненных проверок, всего проверок.
Также на данной вкладке можно выбрать необходимую сессию и нажав на кнопку «Показать результаты» увидеть перечень выполненных контролей, статус завершения Чек-листа, дату и время завершения. А также на данной вкладке имеется возможность удаления черновика авторизованным пользователем, путем выбора ID сессии и нажатия на кнопку «Удалить»
–	вкладка «Аналитика» (административная) - имеет значительные расширения полномой и позволяет увидеть проверки по любому РФ/ВСП, удалять черновики старше 24 часов, уудалять черновики пользователей по ФИО и вернуть завершенную сессию в черновик. 
Для контроля детальной аналитики по проверкам в верхней части вкладки расположены четыре элемента фильтрации. Филиал выбирается из выпадающего списка, сформированного из таблицы filials (поля id и name), с дополнительной опцией «Все». Список ВСП зависит от выбранного филиала: если выбран конкретный филиал, показываются активные ВСП этого филиала (из таблицы vsp, условие filial_id и close_vsp = false); если выбрано «Все», показываются все активные ВСП. Также доступна опция «Все». Период задаётся двумя календарями — «Дата от» и «Дата до». Все фильтры сохраняются и синхронизируются между административными вкладками. При нажатии кнопки «Показать данные» система извлекает сессии из таблицы checklist_sessions с присоединением справочников filials и vsp для получения названий. Затем одним пакетным запросом загружаются все ответы для найденных сессий из таблицы checklist_answers. Отдельно загружается шаблон из checklist_templates. Для каждого пункта шаблона в итоговой таблице создаётся отдельный столбец, показывающий, выполнен ли этот пункт в данной сессии (значение формируется на основе наличия записи в checklist_answers с is_completed = true). В таблице также присутствуют столбцы: ФИО сотрудника, Филиал, ВСП, Дата, Статус (завершена или черновик), Дата и время завершения.

Для возврата завершённой сессии в черновик администратор вводит часть ФИО сотрудника. Система ищет все завершённые сессии (поле status_bul имеет значение «истина»), где ФИО соответствует введённому шаблону, и отображает их списком. Для каждой найденной сессии показывается: идентификатор, ФИО, филиал, ВСП, дата операции, дата завершения. Администратор выбирает нужную сессию и нажимает «Вернуть в черновик». При этом в таблице checklist_sessions для выбранной записи поле status_bul устанавливается в «ложь», а поле completed_at очищается. После этого сессия снова доступна для продолжения заполнения.

Для удаления черновиков старше 24 часов система автоматически находит все сессии, где status_bul имеет значение «ложь», а дата создания (created_at) старше текущего момента более чем на 24 часа. Отображается количество найденных черновиков и таблица с их списком. Администратор должен подтвердить удаление, установив специальный флажок «Я подтверждаю удаление всех черновиков старше 24 часов (нельзя отменить)» нажать на кнопку «Удалить черновики старше 24 часов». После подтверждения для каждой найденной сессии каскадно удаляются все связанные ответы (из таблицы checklist_answers) и сама сессия (из таблицы checklist_sessions).

Для удаления черновиков по ФИО администратор вводит часть ФИО сотрудника. Система находит все черновики (сессии с status_bul равным «ложь»), где ФИО соответствует запросу. Результаты отображаются в редактируемой таблице, где администратор может отметить галочками отдельные строки для удаления, проставить галочку в поле «Удалить» и нажать на кнопку «Подтверждаю удаление». При подтверждении для каждой отмеченной сессии выполняется каскадное удаление ответов и самой сессии.

–	Вкладка «Филиалы (чекбоксы)» - позволяет управлять справочником мигрированных РФ, временной блокировки РФ по использованию Чек-листа.
Отображает список всех филиалов из таблицы filials (поля id, name, check_name, blocked). Для каждого филиала выводятся его название и два чекбокса:
Первый чекбокс — «Альтернативный фильтр». Он управляет значением поля check_name в таблице filials. Когда флажок установлен, при заполнении чек-листа пользователями этого филиала будут использоваться альтернативные описания и фильтры из шаблона (поля с префиксом alt_ в таблице checklist_templates). Когда флажок снят, используются стандартные.
Второй чекбокс — «Блокировка». Он управляет значением поля blocked в таблице filials. Когда флажок установлен, пользователи этого филиала полностью лишаются возможности создавать новые проверки — при попытке они видят сообщение о временном ограничении доступа.
При нажатии кнопки «Сохранить настройки» для каждого филиала выполняется обновление обоих полей в таблице filials.


–	Вкладка «Нерабочие дни (отчет)» - имеет значительные расширения полномочий и позволяет массово добавить выходной день для филиала и нерабочий день (штучно).
В Отчете по нерабочим дням ВСП (администратор) фильтры аналогичны вкладке «Аналитика»: выбор филиала, ВСП, периода дат. При нажатии кнопки «Показать» данные извлекаются из таблицы vsp_non_working_days с присоединением справочников filials и vsp для получения читаемых названий. Результат отображается в редактируемой таблице с колонками: идентификатор записи, филиал, ВСП, дата, причина. Администратор может отметить несколько записей для удаления. При подтверждении все отмеченные записи удаляются из таблицы vsp_non_working_days по их идентификаторам.

Функция «Массовое добавление для всех ВСП филиала»  дает возможность добавить нерабочий день сразу для всех ВСП выбранного филиала. Для этого необходимо выбрать филиал из выпадающего списка, выбрать дату из календаря, указать причину из выпадающего списка и нажать на кнопку «Добавить выходной для всех ВСП филиала. При выполнении система загружает все активные ВСП выбранного филиала (из таблицы vsp, условие filial_id и close_vsp = false). Для каждого ВСП проверяется, существует ли уже запись о нерабочем дне на указанную дату (поиск в vsp_non_working_days по vsp_id и date). Если записи нет, создаётся новая с указанием администратора в качестве автора, кодом филиала, идентификатором ВСП, датой и причиной. Система возвращает статистику: сколько записей добавлено и сколько пропущено из-за того, что они уже существовали.

Функция «Добавить нерабочий день (штучно) дает возможность добавить нерабочий день отдельно по ВСП за один день или период.Для этого необходимо выбрать филиал из выпадающего списка, выбрать ВСП по данному РФ из выпадающего списка, выбрать тип добавления (один день или период), выбрать дату из календаря и указать причину из выпадающего списка. Далее нажать на кнопку «Добавить». При выборе одного дня выполняется одиночная вставка с предварительной проверкой существования. При выборе периода система проходит по всем датам в указанном диапазоне и для каждой выполняет проверку существования записи для данного ВСП. Если записи нет, создаётся новая. Возвращается статистика по добавленным и пропущенным дням.
–	Вкладка «Визуализация (админ)» - тражает информацию по статусу заполнения чек-листов по всем РФ и ВСП РФ
Для использования функции «Статус заполнения чек-листов (администратор) администратор выбирает филиал из выпадающего списка (сформированного из таблицы filials) и дату. При нажатии «Показать статус» выполняются три запроса. Первый получает все активные ВСП выбранного филиала (из таблицы vsp, условие filial_id и close_vsp = false). Второй — список ВСП, для которых на выбранную дату зарегистрирован нерабочий день (из таблицы vsp_non_working_days). Третий — список ВСП, для которых на эту дату существует завершённая проверка (из таблицы checklist_sessions, условие status_bul = true).
Для каждого ВСП вычисляется статус: если ВСП есть в списке нерабочих — «Выходной»; иначе если есть завершённая проверка — «Заполнен»; иначе — «Не заполнен». Строится круговая диаграмма, где ВСП со статусом «Выходной» исключаются, а оставшиеся делятся на заполненные и незаполненные с цветовой индикацией (зелёный и красный) и процентным соотношением. Под диаграммой отображается таблица со столбцами «ВСП» и «Статус», строки которой раскрашены в зависимости от статуса.

Функция «Сводка по всем филиалам» позволяет дополнительно для этой же даты построить сводный статус по всем филиалам. Для каждого филиала система определяет количество активных ВСП, количество ВСП с нерабочим днём и количество ВСП с завершённой проверкой. На основе этих данных вычисляется общий статус филиала: если все активные ВСП — нерабочие, статус «Все выходные»; если все активные ВСП (исключая нерабочие) имеют завершённую проверку — «Заполнен»; если есть хотя бы одна завершённая проверка, но не все — «Частично»; если нет ни одной завершённой проверки — «Не заполнен».
Результаты выводятся в виде круговой диаграммы по статусам филиалов и таблицы с колонками: Филиал, Статус, Всего ВСП, Активных ВСП (исключая нерабочие), Заполнено ВСП. Строки таблицы раскрашены в зависимости от статуса.
