БИ на разработку приложения «Чек-лист завершения операций ВСП/РФ»
1. Общие сведения
Параметр	Значение
Наименование системы	Приложение «Чек-лист завершения операций ВСП/РФ»
Цель системы	Автоматизация процесса комплексного контроля полноты и правильности формирования бухгалтерских записей перед блокированием операционного дня, снижение операционных рисков и исключение ручного мониторинга исполнителями.
Описание задачи	Разработать веб-приложение с двумя изолированными ролевыми панелями (Панель сотрудника РФ/ВСП и Административная панель ЕСЦ) для автоматизации создания, ведения, завершения черновиков и итоговых чек-листов, управления справочниками филиалов и ВСП, учёта нерабочих дней, а также формирования наглядной аналитики и визуализации статуса выполнения проверок.
Целевая аудитория	63 участника РФ, 1363 участника ВСП РФ и администраторы ЕСЦ
Источники данных	АБС (отчёты), Keycloak, внутренние справочники ЕСЦ, таблицы локального хранения приложения
 
2. Ролевая модель
Роль	Описание
Сотрудник РФ/ВСП	Ответственный сотрудник филиала, осуществляющий учётные операции и заполняющий чек-лист завершения дня.
Администратор ЕСЦ	Сотрудник Единого сервисного центра, управляющий шаблонами проверок, справочниками филиалов/ВСП, блокировками, возвратом сессий и глобальной аналитикой.

3. Ключевые бизнес-правила
ID	Описание правила	Уровень применения
BR-01	На один ВСП в день может быть создана только одна проверка (статус: черновик или завершено).	Панель сотрудника
BR-02	Один пользователь не может иметь более одного незавершённого черновика за текущую дату.	Панель сотрудника
BR-03	Если филиал заблокирован (blocked = true), создание новых проверок полностью запрещено. Пользователь видит предупреждение, доступ к действию блокируется.	Панель сотрудника
BR-04	Выбор между стандартными и альтернативными фильтрами при заполнении зависит от настройки филиала (check_name).	Панель сотрудника
BR-05	Удаление черновика разрешено только его владельцу; при удалении каскадно удаляются все связанные ответы.	Панель сотрудника
BR-06	При удалении пункта шаблона каскадно удаляются все связанные с ним ответы, после чего оставшиеся пункты автоматически перенумеровываются.	Административная панель
BR-07	При массовых операциях с нерабочими днями перед созданием каждой записи проверяется её отсутствие для того же ВСП на ту же дату –дубликаты не создаются	Административная панель
BR-08	Установка блокировки филиала немедленно запрещает создание новых проверок, но не затрагивает уже существующие черновики.	Административная панель
BR-09	Флаг альтернативных фильтров влияет на отображаемые поля шаблона при заполнении чек-листа.	Административная панель
BR-10	При возврате завершённой сессии в черновик у неё очищается дата завершения и меняется статус, что делает её снова доступной для редактирования.	Административная панель
BR-11	Возможность самостоятельного управления справочником РФ и ВСП при открытии/закрытии с автоматическими корректировками по всем необходимым вкладкам.	Административная панель
4. Функциональные требования
4.1. Панель сотрудника РФ/ВСП
4.1.1. Авторизация и начальные данные
·	Способ 1: Корпоративная система аутентификации Keycloak.
·	Способ 2: Ручной ввод логина в формате rf_familiya_io. Система ищет запись в users, извлекает full_name, name_filial, name_vsp.
·	Валидация: По name_filial запрашивается filials (определяется blocked). По name_vsp запрашивается vsp (определяется активность).
·	Ограничения: При отсутствии пользователя — вывод ошибки. При blocked = true — запрет доступа и блокировка интерфейса.
·	Контекст: После входа все извлечённые данные фиксируются и передаются на все последующие этапы.
4.1.2. Структура интерфейса Экранная форма разделена на две зоны:
·	Левая боковая панель: Информация о пользователе (ФИО, логин), кнопка смены пользователя, блок входа в админ-панель (если есть права).
·	Центральная область: Набор вкладок: «Новая проверка», «История проверок», «Нерабочие дни ВСП», «Аналитика по филиалу», «Визуализация».
4.1.3. Вкладка «Новая проверка»
·	При открытии отображаются ФИО, логин, ВСП (по умолчанию из авторизации, меняется через выпадающий список активных ВСП филиала), дата (текущая, не редактируется).
·	Логика создания черновика (3 проверки):
1.	Поиск незавершённого черновика текущего пользователя за сегодня (checklist_sessions). Если найден — вместо кнопки создания выводятся «Продолжить» и «Удалить».
2.	Проверка наличия любой сессии (черновик/завершено) для выбранного ВСП на сегодня. Если есть — блокировка создания.
3.	Проверка сохранённого флага блокировки филиала. Если заблокирован — кнопка недоступна.
·	Создание сессии: При нажатии «Начать заполнение» создаётся запись в checklist_sessions (status_bul = false). Интерфейс переключается на форму.
·	Загрузка контента: Шаблон из checklist_templates (сортировка по item_order), сохранённые ответы из checklist_answers (по session_id). Определение типа фильтров по check_name филиала.
·	Отрисовка пунктов: Порядковый номер, наименование, кнопка «Подробнее» (раскрывает основной и дополнительный фильтры). Плейсхолдеры: [Дата1], [Дата1 гггг-мм-дд], [Дата1 дд.мм.гггг], [РФ], [РФ1]. Кнопка копирования фильтров. Чекбокс «Выполнено» (привязка к is_completed).
·	Кнопки управления:
·	Сохранить черновик: Фиксирует ответы в БД, статус остаётся «черновик», сессия помечается как явно сохранённая. При повторном входе появляется запись о черновике.
·	Назад: Если не сохранялся — удаляет сессию и ответы. Если сохранялся — возврат без удаления.
·	Предпросмотр: Локальный подсчёт выполненных/всего пунктов.
·	Завершить проверку: Проверяет отметку всех пунктов. При успехе — статус status_bul = true, фиксация completed_at, возврат на стартовую вкладку.
4.1.4. Вкладка «История проверок»
·	Таблица всех проверок текущего пользователя в его ВСП (объединённый запрос к сессиям, филиалам, ВСП).
·	Поля: ID сессии, дата, филиал, ВСП, статус (рассчитывается), время начала, время завершения, кол-во выполненных/всего.
·	Действия: Выбор сессии → «Показать результаты» (загрузка полных данных: сессия, ответы, шаблон, список с отметками).
·	Удаление черновика: Ввод ID сессии → проверка владельца и статуса «Черновик» → подтверждение → каскадное удаление ответов и сессии.
4.1.5. Вкладка «Нерабочие дни ВСП»
·	Подстановка ВСП по умолчанию (можно сменить через список активных).
·	Выбор даты из календаря, причины из списка (ремонт, праздник, «Другое» с ручным полем).
·	Сохранение в vsp_non_working_days.
·	Фильтр истории: По умолчанию показываются записи текущего ВСП. Флажок «Показать все выходные вашего ВСП» расширяет выборку. Кнопка «Удалить» для каждой записи (с проверкой принадлежности к филиалу).
4.1.6. Вкладка «Аналитика по филиалу»
·	Филиал определён автоматически. Выбор периода через два календаря.
·	Таблица всех проверок: Запрос без фильтрации по пользователю (только филиал). Столбцы: ID, сотрудник, дата, ВСП, статус, время начала/завершения, кол-во проверок.
·	Управление черновиками: Фильтрация только по статусу «Черновик» текущего ВСП. Массовое удаление с подтверждением (каскадный сброс ответов и сессий).
4.1.7. Вкладка «Визуализация»
·	Выбор даты. Нажатие «Показать статус».
·	Логика расчёта статусов: Запрос активных ВСП (vsp), ВСП с нерабочим днём (vsp_non_working_days), ВСП с завершённой проверкой (checklist_sessions).
·	Статусы: Нерабочий день → «Выходной» / Завершённая проверка → «Заполнен» / Иначе → «Не заполнен».
·	Отображение: Круговая диаграмма (исключая «Выходные») с процентами «Заполнено/Не заполнено» и раскраской (зелёный/красный). Таблица со строками, раскрашенными по статусу.
4.2. Административная панель ЕСЦ
4.2.1. Авторизация администратора
·	Способ 1: Keycloak. Автоматический вход при наличии email в зарезервированном списке. Активация через флажок на боковой панели.
·	Способ 2: Ручной ввод пароля из конфигурации. При совпадении режим активируется.
·	При успешном входе на боковой панели появляются админ-элементы, в центре — новые вкладки.
4.2.2. Левая панель (Управление шаблонами)
·	Текущие проверки: Свёрнутый блок с пунктами checklist_templates (id, item_order, description).
·	Добавить проверку: Заполнение полей (description, filter_value, alt_filter_value и др.). Выбор позиции вставки: в конец или перед конкретным пунктом (сдвиг item_order для последующих пунктов, автоматическая вставка).
·	Редактировать/Удалить/Переместить:
·	Выбор из выпадающего списка с предзаполнением полей. Кнопка «Обновить» сохраняет изменения.
·	Удаление: Каскадное удаление ответов в checklist_answers, удаление пункта в checklist_templates, автоматическая перенумерация оставшихся пунктов.
·	Перемещение: Сдвиг вверх/вниз на 1 позицию, либо перемещение на конкретную позицию с сдвигом промежуточных пунктов и обновлением item_order.
4.2.3. Вкладка «Новая проверка» (Админ)
·	Полный функционал панели сотрудника (создание черновика, автоподстановка данных, проверка на дубли и блокировки, работа с интерфейсом). Используется администратором для самостоятельного заполнения.
4.2.4. Вкладка «История проверок» (Админ)
·	Полностью аналогична панели сотрудника, включая просмотр результатов, удаление черновиков по ID.
4.2.5. Вкладка «Аналитика» (Админ)
·	Фильтры: Филиал (с опцией «Все»), ВСП (зависит от филиала, с опцией «Все»), период дат. Сynchronизация с другими админ-вкладками.
·	Детальная таблица: Запрос сессий + ответы + шаблон. Для каждого пункта шаблона создаётся отдельный столбец со статусом выполнения (is_completed). Столбцы: ФИО, Филиал, ВСП, Дата, Статус, Время завершения.
·	Функции администратора:
·	Вернуть в черновик: Ввод части ФИО → поиск завершённых сессий (status_bul = true) → выбор сессии → сброс status_bul на false, очистка completed_at.
·	Удалить черновики старше 24 часов: Автопоиск сессий с status_bul = false и created_at > 24ч. Отображение списка. Обязательный флажок подтверждения → каскадное удаление.
·	Удалить черновики по ФИО: Поиск черновиков по шаблону ФИО → таблица с галочками → кнопка «Подтверждаю удаление» → каскадное удаление выбранных.
4.2.6. Вкладка «Филиалы (чекбоксы)»
·	Таблица филиалов (id, name, check_name, blocked).
·	Два чекбокса на строку:
1.	Альтернативный фильтр → обновляет check_name.
2.	Блокировка → обновляет blocked.
·	Кнопка «Сохранить настройки» применяет изменения пакетно.
4.2.7. Вкладка «Нерабочие дни (отчет)»
·	Отчёт: Фильтры (филиал, ВСП, период). Таблица с ID, названием филиала/ВСП, датой, причиной. Массовое удаление отмеченных записей.
·	Массовое добавление для всех ВСП филиала: Выбор филиала, даты, причины → кнопка → загрузка активных ВСП филиала → проверка на дубли в vsp_non_working_days → создание записей → вывод статистики (добавлено/пропущено).
·	Добавить нерабочий день (штучно): Выбор филиала, ВСП, типа (один день/период), даты, причины → кнопка. При выборе периода система проходит по датам диапазона, проверяет дубли, создаёт отсутствующие записи → статистика.
4.2.8. Вкладка «Визуализация (админ)»
·	Статус заполнения (по филиалу): Аналогично панели сотрудника, но с выбором любого филиала. Расчёт статусов, диаграмма, раскрашенная таблица.
·	Сводка по всем филиалам: Для выбранной даты строится отчёт по всем филиалам.
·	Расчёт: Всего ВСП, Активных ВСП (искл. нерабочие), Заполнено ВСП.
·	Логика статуса филиала: Все нерабочие → «Все выходные» / Все активные заполнены → «Заполнен» / Есть заполненные, но не все → «Частично» / Нет заполненных → «Не заполнен».
·	Вывод: Круговая диаграмма по статусам филиалов + таблица с цветовой индикацией строк.
5. Требования к базе данных
Для реализации описанных требований необходимо предоставить и использовать следующие таблицы:
Таблица	Назначение	Ключевые поля
users	Данные сотрудников	name (логин), full_name, name_filial, name_vsp
filials	Справочник филиалов	id, name, blocked (boolean), check_name (boolean)
vsp	Справочник ВСП	id, name, filial_id, close_vsp (boolean)
checklist_templates	Шаблоны проверок	id, item_order, description, filter_value, additional_info, alt_filter_value, alt_additional_info, alt_events_value
checklist_sessions	Сессии чек-листов	id, user_name, filial_id, vsp_id, operation_date, status_bul (boolean), created_at, completed_at
checklist_answers	Ответы в сессиях	id, session_id, template_item_id, is_completed (boolean)
vsp_non_working_days	Учёт выходных ВСП	id, user_name, filial_id, vsp_id, operation_date, reason
6. Требования к безопасности и интерфейсу
·	Аутентификация: Интеграция с Keycloak + резервный механизм ввода пароля для администратора.
·	Разграничение прав: Жёсткое разделение данных между пользователями. Доступ к админ-функциям только после верификации роли.
·	Целостность данных: Реализация каскадных операций удаления (черновики → ответы, пункты шаблона → ответы).
·	Интерфейс: Корпоративный стиль, адаптивная верстка под десктоп, отсутствие канцелярита в формулировках, четкая визуальная индикация статусов (цветовое кодирование в таблицах и диаграммах).
